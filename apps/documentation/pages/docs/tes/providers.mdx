# TES Providers

The `@elixir-cloud/tes` package provides providers for connecting to GA4GH Task Execution Service (TES) APIs. The main provider is `RestTesProvider` which implements the `TesProvider` interface for REST-based TES endpoints.

<Callout type='info'>
  **Quick Start**: Create a `RestTesProvider` with your TES server URL and pass it to TES components
  to start submitting and monitoring tasks. Components also accept a `baseUrl` instead, in which
  case a `RestTesProvider` is created for you. If both are set, `provider` wins.
</Callout>

## TesProvider Interface

The `TesProvider` interface defines the operations that all TES providers must implement:

```typescript
export interface TesProvider {
  // Service information
  getServiceInfo(): Promise<ServiceInfo>;

  // Task management
  listTasks(params?: ListTasksParams): Promise<TaskListResponse>;
  getTask(taskId: string, view?: TaskView): Promise<Task>;
  createTask(request: TaskRequest): Promise<TaskId>;
  cancelTask(taskId: string): Promise<void>;
}
```

## RestTesProvider

The `RestTesProvider` is the main implementation that communicates with TES APIs using REST/HTTP.

### Constructor

```typescript
constructor(baseUrl: string)
```

**Parameters:**

- `baseUrl`: The base URL of the TES API endpoint (e.g., `https://protes.rahtiapp.fi/ga4gh/tes/v1`)

## Provider Methods

### getServiceInfo()

Retrieves information about the TES service.

```typescript
getServiceInfo(): Promise<ServiceInfo>
```

### listTasks()

Retrieves a list of tasks with optional pagination, view and filters.

```typescript
listTasks(params?: ListTasksParams): Promise<TaskListResponse>
```

### getTask()

Gets a specific task. `view` defaults to `FULL` and controls how much of the task is returned.

```typescript
getTask(taskId: string, view?: TaskView): Promise<Task>
```

### createTask()

Submits a new task for execution.

```typescript
createTask(request: TaskRequest): Promise<TaskId>
```

### cancelTask()

Cancels a task.

```typescript
cancelTask(taskId: string): Promise<void>
```

## Type Definitions

### State

```typescript
type State =
  | 'UNKNOWN'
  | 'QUEUED'
  | 'INITIALIZING'
  | 'RUNNING'

  | 'COMPLETE'

  | 'SYSTEM_ERROR'
```

### TaskView

```typescript
// MINIMAL: id and state only. BASIC: everything except large log/content fields.
type TaskView = 'MINIMAL' | 'BASIC' | 'FULL';
```

## Using with Components

### Task Submission

```tsx copy
import { RestTesProvider } from '@elixir-cloud/tes/providers';
import { ECCClientGa4ghTesRunCreate } from '@elixir-cloud/tes/react';

function TaskSubmitter() {
  const provider = new RestTesProvider('https://protes.rahtiapp.fi/ga4gh/tes/v1');

  return (
    <ECCClientGa4ghTesRunCreate
      provider={provider}
      onEccRunSubmitted={(event) => {
        console.log('Task submitted:', event.detail.runId);
      }}
      onEccRunCreateFailed={(event) => {
        console.error('Submission failed:', event.detail.error);
      }}
    />
  );
}
```

### Task Monitoring

```tsx copy
import { RestTesProvider } from '@elixir-cloud/tes/providers';
import { ECCClientGa4ghTesRun } from '@elixir-cloud/tes/react';

function TaskMonitor({ runId }) {
  const provider = new RestTesProvider('https://protes.rahtiapp.fi/ga4gh/tes/v1');

  return (
    <ECCClientGa4ghTesRun
      provider={provider}
      runId={runId}
      onEccRunLogChanged={(event) => {
        console.log('Task state:', event.detail.task.state);
      }}
    />
  );
}
```

## Custom Providers

For custom use cases, you can extend `RestTesProvider` or implement the `TesProvider` interface directly. This is useful for:

- Adding custom authentication
- Implementing caching or offline support
- Connecting to non-standard or non-REST APIs
- Adding custom error handling or retry logic

```tsx copy
// Example: Custom provider implementing the interface directly
import type { TesProvider } from '@elixir-cloud/tes/providers';

const provider: TesProvider = {
  getServiceInfo: async () => ({}),
  listTasks: async () => ({ tasks: [] }),
  getTask: async (id) => ({ id, state: 'QUEUED' }),
  createTask: async () => ({ id: 'my-task' }),
  cancelTask: async () => {},
};
```


```tsx copy
// Example: Custom provider with authentication
import { RestTesProvider } from '@elixir-cloud/tes/providers';

class AuthTesProvider extends RestTesProvider {
  private token: string;

  constructor(baseUrl: string, token: string) {
    super(baseUrl);
    this.token = token;
  }

  protected fetch(input: RequestInfo | URL, init: RequestInit = {}) {
    const headers = new Headers(init.headers);
    headers.set('Authorization', `Bearer ${this.token}`);
    return super.fetch(input, { ...init, headers });
  }
}

const provider = new AuthTesProvider(
  'https://protes.rahtiapp.fi/ga4gh/tes/v1',
  'your-access-token'
);
```

<Callout type='warning'>
  Tokens used in browser code are visible to users. Prefer short-lived tokens, and never embed long-lived secrets in client-side bundles.
</Callout>

For comprehensive patterns and examples, see the [Providers Overview](/docs/providers) documentation.

## Testing

Test your TES provider setup:

```tsx copy
async function testTesProvider(provider) {
  try {
    console.log('Testing TES provider...');

    // Test service info
    const serviceInfo = await provider.getServiceInfo();
    console.log('Service info:', serviceInfo.name);

    // Test listing tasks
    const tasks = await provider.listTasks({ pageSize: 5, view: 'MINIMAL' });
    console.log(`Found ${tasks.tasks.length} recent tasks`);

    console.log('TES provider is working correctly!');
    return true;
  } catch (error) {
    console.error('TES provider test failed:', error);
    return false;
  }
}

// Usage
const provider = new RestTesProvider('https://protes.rahtiapp.fi/ga4gh/tes/v1');
testTesProvider(provider);
```
