## Overview

The `ecc-client-elixir-cloud-registry-service-create` component provides a comprehensive form interface for creating new service registrations in the Elixir Cloud Registry. It includes validation, error handling, and support for both basic and advanced service metadata.

<Callout type='info'>
  This component extends the GA4GH Service Registry specification with additional features specific to the Elixir Cloud ecosystem.
</Callout>

            onEccServiceCreated={handleServiceCreated}

    }

## Properties

| Property   | Type                    | Default | Description                                                                    |
|------------|-------------------------|---------|--------------------------------------------------------------------------------|
| `provider` | `CloudRegistryProvider` | `null`  | Data provider for service creation operations (see [Providers](/docs/cloud-registry/providers)) |
| `environments` | `(string \| EnvironmentOption)[]` | `prod`, `test`, `dev`, `staging` | Environments to offer if the registry doesn't publish its own |

### `provider`
The data provider responsible for creating services in the registry. You must provide a provider that implements the `CloudRegistryProvider` interface, which extends the base `ServiceRegistryProvider` with creation capabilities. See the [Providers documentation](/docs/cloud-registry/providers) for detailed information about available providers and how to create custom ones.

<Callout type='warning'>
  The provider must support service creation operations. If no provider is provided, the component will emit a validation error.
</Callout>

You can replace the provider at any time, e.g. when the user's token changes: the component then loads the service types from the new provider and sends all later requests through it. It keeps the form's input. `provider` takes precedence over `baseUrl`; if you remove it, the component uses `baseUrl` again.

<Callout type='info'>
  Each new provider object makes the component load the service types again. In React, create the provider only when its inputs change, e.g. with `useMemo(() => new RestCloudRegistryProvider(url), [url])`, not on every render.
</Callout>

### `environments`
The environments that the form offers for `environment`, as values or `{ value, label }` objects (`EnvironmentOption`); an empty list allows any value, and the form then shows a text field. The default is the GA4GH suggestion: `prod`, `test`, `dev` and `staging`.

Cloud Registry 0.6.0 and later publish the environments they allow (`registration_rules.environments` of `GET /service-info`, configured with `custom.endpoints.services.environments`). The form reads them and offers these instead, with the labels given in `environments` (or the default labels); `environments` applies only to registries and providers without these rules. A registry that allows any environment (an empty list) gets a text field, whatever `environments` says. A chosen environment that is no longer offered is cleared. As an attribute, `environments` takes a JSON list.

## Events

| Event Name                          | React Event Name                     | Detail Type                                              | Description                                          |
|-------------------------------------|--------------------------------------|----------------------------------------------------------|------------------------------------------------------|
| `ecc-service-created`               | `onEccServiceCreated`                | `{ serviceId: string, serviceData: object, message: string }` | Fired when a service is successfully created        |
| `ecc-service-create-failed`         | `onEccServiceCreateFailed`           | `{ error: string, status?: number, title?: string, detail?: string, serviceId?: string, cause?: unknown }` | Fired when service creation or loading the service types fails |
| `ecc-service-create-validation-failed` | `onEccServiceCreateValidationFailed` | `{ error: string }`                                      | Fired when there are validation errors              |

### `ecc-service-created`
Emitted when a service is successfully created in the registry, providing the new service ID, the submitted service data, and a success message.

### `ecc-service-create-failed`
Emitted when service creation or loading the service types fails due to server errors, network issues, or other runtime problems.

- `error`: what went wrong, e.g. the registry's explanation (the problem's `detail`); if the service types can't be loaded, it starts with "Failed to load service types";
- `status`: the HTTP status of the failed request, if there was one, e.g. `401` (log in) or `403` (no role on the service);
- `title`, `detail`: the problem details that the registry sent, if any;
- `serviceId`: the ID of the existing service, for duplicate registrations (`409`);
- `cause`: the error that the provider threw.

The component reads `status`, `title`, `detail` and `serviceId` from the error that the provider throws, a `CloudRegistryError` for `RestCloudRegistryProvider` (see [Errors](/docs/cloud-registry/providers#errors)). Custom providers can throw errors with the same fields.
