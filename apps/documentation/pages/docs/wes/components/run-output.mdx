## Overview

The `ecc-client-ga4gh-wes-run-output` component shows one output of a workflow run, as the workflow's [GA4GH IO Schema](https://github.com/elixir-cloud-aai/ga4gh-io-schema) says: its title and description, and its files with the viewer of the output's `x-ga4gh-ui-widget` hint. It follows version 0.3.0 of the profile, which has no release yet; the component and these docs refer to commit [`2c3dc49`](https://github.com/elixir-cloud-aai/ga4gh-io-schema/tree/2c3dc49ad89f0a556272f160369a2a2d7a21dac3) ([UI widgets](https://github.com/elixir-cloud-aai/ga4gh-io-schema/blob/2c3dc49ad89f0a556272f160369a2a2d7a21dac3/docs/specification/widgets.md), [Outputs](https://github.com/elixir-cloud-aai/ga4gh-io-schema/blob/2c3dc49ad89f0a556272f160369a2a2d7a21dac3/docs/specification/outputs.md) and [Rendering schemas and outputs](https://github.com/elixir-cloud-aai/ga4gh-io-schema/blob/2c3dc49ad89f0a556272f160369a2a2d7a21dac3/docs/security.md#rendering-schemas-and-outputs)).

It takes the schema of one output (a property of `outputs` in the IO schema) and its value in the *normalised outputs object* of the run, which a normaliser builds from the engine-specific `RunLog.outputs`. It doesn't normalise outputs itself.

| Output | Shown as |
|--------|----------|
| A file with `table-viewer` | A table of the CSV or TSV file: the first row is the header, every cell is text, at most `maxRows` rows and `maxColumns` columns |
| A file with `html-viewer` | The HTML file in an `iframe` with an empty `sandbox` attribute and a Content Security Policy that blocks external loads |
| Any other file or directory (no viewer, another or unknown viewer, `custom:` viewers) | Its URI as text and a download button |
| A list of files, or files keyed by name | One entry per file, labelled by its file name or key, each with the viewer of `items` or `additionalProperties`; at most `maxFiles` entries |
| Any other value (a number, a string, a record) | The value as text |

The component is deliberately minimal: a library of widgets for inputs and outputs may replace or wrap it later.

## Security

Outputs come from the run, which may have processed files supplied by users, and the schema from the workflow's author, so the component treats both as untrusted:

- **Text:** the title, the description (also Markdown) and the cells of tables are shown as text; markup in them stays visible as markup and never reaches the page.
- **Allow-list:** every URI is checked against `allowedSchemes` and, if the file reference has `schemes`, against those too, before anything is fetched or offered for download. URIs with other schemes, paths, control characters or surrounding whitespace are shown as text, with a note. `javascript`, `data`, `blob`, `file` and the other schemes that run code or refer to local data are never allowed, even if listed.
- **HTML:** shown only in an `iframe` with an empty `sandbox` attribute (no scripts, forms, pop-ups or navigation of the page, and an opaque origin) and `srcdoc` that starts, before the untrusted markup, with a `<meta>` Content Security Policy (`default-src 'none'; img-src data:; style-src 'unsafe-inline'`), a `no-referrer` referrer policy and `<base target="_blank">`, so that clicked links can't load other pages into the frame (new windows are blocked by the sandbox). If the file can't be fetched or is larger than `maxBytes`, it is offered for download only.
- **Downloads, never direct links:** stored files can contain active content (HTML, SVG, PDF) whatever their name. The component never links to them; its download button asks the provider for a download URL, which must make the storage or a proxy send `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`.
- **Limits:** viewers read at most `maxBytes` bytes of a file, tables show at most `maxRows` rows and `maxColumns` columns, and lists show at most `maxFiles` files; the rest is offered for download. Viewers load one file at a time.

## Output provider

The component fetches and downloads files only through a `WesOutputProvider`, so that the app adds credentials and decides how storage URIs (e.g. `s3://` or `drs://`) become URLs that the browser can use. It calls the provider only for URIs that pass the allow-list.

```typescript
interface WesOutputProvider {
  // Content of a file, for a viewer; responses that aren't ok are errors
  fetchOutput(uri: string, init?: { signal?: AbortSignal }): Promise<Response>;
  // An http(s) URL whose response has Content-Disposition: attachment
  // and X-Content-Type-Options: nosniff
  getDownloadUrl(uri: string): Promise<string>;
}
```

<Callout type="warning">
  The download URL must make the browser save the file, not show it: set `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff` in a proxy, or make the storage set them (e.g. the `response-content-disposition` parameter of a presigned S3 URL). The `download` attribute of the link that the component uses works only for URLs on the page's own origin. The component refuses download URLs that aren't `http:` or `https:`.
</Callout>

Without a provider, the component shows the URIs of files as text, without viewers or downloads.

## Properties

| Property | Attribute | Type | Default | Description |
|----------|-----------|------|---------|-------------|
| `name` | `name` | `string` | `""` | Name of the output, its key in the normalised outputs object; the title if the schema has none. |
| `schema` | | `object` | `undefined` | Schema of the output: the property of `outputs` of the IO schema. |
| `value` | | `unknown` | `undefined` | Value of the output in the normalised outputs object. |
| `provider` | | `WesOutputProvider` | `undefined` | Fetches files for viewers and returns download URLs (see [Output provider](#output-provider)). |
| `allowedSchemes` | `allowed-schemes` | `string[]` | `["drs", "https"]` | URI schemes that may be fetched or downloaded; the attribute separates them by spaces or commas. Anything other than an array, or removing the attribute, means the default. Set the deployment's allow-list: `drs`, `https`, the object-store schemes it supports (e.g. `s3`), and `http` only for internal networks. |
| `maxRows` | `max-rows` | `number` | `1000` | Rows that a table shows at most. |
| `maxColumns` | `max-columns` | `number` | `100` | Columns that a table shows at most. |
| `maxFiles` | `max-files` | `number` | `50` | Files of a list, or of files keyed by name, that are shown at most. |
| `maxBytes` | `max-bytes` | `number` | `5242880` (5 MiB) | Bytes of a file that a viewer reads at most. |

Invalid limits (negative or not a number) mean the default.
