This release brings `@elixir-cloud/tes` to the provider architecture of the other client packages and publishes it as `2.0.0-alpha.51`, its first release since `1.0.1`. TES components now take a `provider`, so apps can send the logged-in user's access token with every request by subclassing `RestTesProvider` and overriding its `fetch` method (see the [TES providers](https://cloud-components.readthedocs.io/en/latest/docs/tes/providers) page). Tasks created with the form now contain their `outputs`. The release also adds filters, pages and row actions to the Service Registry list, and moves `@elixir-cloud/cloud-registry` to the camelCase names of Cloud Registry 1.0.0rc2. As for the other packages, the dist-tag `latest` of `@elixir-cloud/tes` moves to this prerelease; apps that depend on `^1.0.1` keep `1.0.1`.

## Breaking changes

- `@elixir-cloud/tes`: `<ecc-client-ga4gh-tes-create-run>` is now `<ecc-client-ga4gh-tes-run-create>`, the property `baseURL` is now `baseUrl`, and components are imported from `@elixir-cloud/tes/components/run-create/index.js` (and so on) instead of `@elixir-cloud/tes/dist/components/create-run/index.js` (#443, #516)
- `@elixir-cloud/cloud-registry`: the create form reads `registrationRules` from the registry's service info, with the camelCase names of Cloud Registry 1.0.0rc2 (`urlSchemes`, `serviceTypes`, `maxUnusedServiceTypes`, `maxServicesPerUser`); against older registries, it logs a warning and uses its properties (#562, #563)

## Features

- `@elixir-cloud/tes`: components accept a `provider` (`TesProvider`, with `RestTesProvider` as the REST implementation), which takes precedence over `baseUrl`, emit typed events, use the design package's styles, and a new `<ecc-client-ga4gh-tes-run>` shows a single task (#443, #516)
- `@elixir-cloud/service-registry`: the services list has filters by type, organization and environment, client-side pages (`page-size`), a `rowActions` render hook, and selects a service on a row click; search filters the loaded list and also matches the service URL (#455, #575)
- `@elixir-cloud/design`: inputs and text areas have a `label` property, forwarded to the native control as `aria-label` (#443, #516)

## Security

- Update transitive dependencies with known advisories (#556, #559)
- Run the build scripts' commands without a shell and escape generated template literals correctly (#558, #560)
- `@elixir-cloud/service-registry`: open organization links only for `http:` and `https:` URLs, with `noopener` and `noreferrer` (#455, #575)

## Fixes

- `@elixir-cloud/tes`: the create form sends the task's `outputs` (the request used the field `output`, which TES services ignore) (#574, #516)
- `@elixir-cloud/wes`: borders render inside the components' shadow roots, and the success message of the create form follows the theme and is announced to screen readers (#443, #516)
